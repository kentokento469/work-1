# Phase 7 開発計画（案）— Phase 6 からの引き継ぎ

> **整合性の確認（2026-10-16）**：Phase 7 はオーナーの指示により「汎用タスク管理システムの構築と業務管理基盤への統合」として実施した（結果は [PHASE7_RESULTS.md](PHASE7_RESULTS.md)）。本書の項目のうち、実機検証・承認フロー・担当者ごとの通知は Phase 8〜16 計画（[PHASE8_16_PLAN.md](PHASE8_16_PLAN.md)）の該当 Phase に引き継いだ。期限間近の通知は Phase 7 でも採用していない（ダッシュボードの「もうすぐ期限」と、タスク画面の「今日」「今週」で確認する）。

Phase 6 で、通知・件数・関連情報を実データから導出する共通の仕組み（`domain/notifications.ts`・`ui/notices.tsx`・`app/focus.ts`）にまとめた。
新しい機能で「対応が必要なこと」が増えたら、`deriveNotices()` に通知の種類を1つ追加するだけで、ナビの件数・各画面の「要対応」・通知センター・詳細画面の理由表示・履歴がそろって動く。

## 1. 最初に行うこと（実機検証）
| 項目 | 内容 |
| --- | --- |
| iPhone Safari | バッジ・ベルのタップ、通知から移動した後の強調表示とスクロール、戻る（標準スワイプ）、要対応の展開、ダークモードでの区分の色 |
| ホーム画面に追加 | 独自スワイプ・通知からの移動・再読み込み後の既読 |
| Phase 1〜5 の持ち越し | カメラ・HEIC・共有シート・OCR の速度・日本語キーボード |

## 2. 通知の拡張
| 項目 | 内容 |
| --- | --- |
| 期限間近の通知（任意） | 3日以内の期限を「注意」として表示するかを設定で選べるようにする（現在はダッシュボードのみ） |
| 担当者ごとの通知 | 認証・利用者の概念が入った段階で「自分の担当」に絞り込む（現在は端末内の全件） |
| 承認フロー | 発注書・書類・自動化提案の「申請 → 承認 → 確定」を共通化し、承認待ちの通知に承認者・差し戻し理由を表示 |
| 通知の自動テストの拡大 | 入社準備・発注書の承認待ちを E2E で個別に検証（現在は単体テストと種類ごとの到達確認） |

## 3. 実運用に向けた基盤（変わらず必要）
認証・権限管理・複数ユーザーの同時利用・サーバー側のデータ保護・プッシュ通知は未実装（デモ環境）。導入する場合は外部サービスの利用となるため、オーナーの承認を得てから行う。
