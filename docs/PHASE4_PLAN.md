# Phase 4 開発計画（案）— Phase 3 時点の計画

> **この文書は Phase 3 終了時点の計画です。** Phase 4 では「書類処理・OCR・CSV自動化」を実装しました（結果は [PHASE4_RESULTS.md](PHASE4_RESULTS.md)）。承認フロー・請求書と発注書の照合などの残りの項目は [PHASE5_PLAN.md](PHASE5_PLAN.md) に引き継いでいます。

Phase 3 で「社員（入社・異動・退職）」「問い合わせ（故障）」「在庫・資産・発注」が自動化エンジンでつながり、
提案 → 承認 → 実行 → 履歴 の流れが部門をまたいで動くようになった。
Phase 4 では、(1) 実機と実データでの検証、(2) 自動化エンジンへの承認フローと新モジュールの追加、(3) 実運用への基盤、の順に進める。

## 1. 最初に行うこと（検証・品質）

| 項目 | 内容 | 理由 |
| --- | --- | --- |
| **実機 iPhone Safari での検証** | 数値入力キーボード、ネイティブ選択ピッカー、ホーム画面追加時の表示、長い一覧のスクロール、IndexedDB の保存容量・消去条件 | Phase 1〜3 を通じて未実施（Chromium のエミュレーションのみ） |
| 大量データでの性能測定 | 品目 300・資産 1,000・入出庫履歴 50,000・問い合わせ 5,000 程度で、一覧・在庫計算・自動化判定・バックアップの所要時間を計測 | 変更のたびに全データを再読込する構成のため、規模が増えると遅くなる可能性がある |
| ユーザビリティテスト | 総務・情シス担当者を想定し、入社準備・発注・故障対応の所要時間と迷った箇所を記録 | 操作回数は計測済みだが、時間・理解度は未計測 |

## 2. 機能（優先度：高）

| 項目 | 内容 | 再利用する Phase 1〜3 の仕組み |
| --- | --- | --- |
| 承認フロー（ワークフロー） | 自動化の提案・発注書・請求書を「申請 → 承認者 → 確定」の共通フローに。承認者・代理承認・差し戻し理由・承認期限 | 発注書の状態遷移、自動化の提案（承認時の再判定）、処理履歴 |
| 請求書・領収書処理 | 受領 → 内容入力 → 勘定科目の候補 → 承認 → 支払タスク。**発注書・入荷記録との照合（数量・金額の三点照合）**、重複受領の検出 | 発注書（PO番号・入荷数・単価）、分類エンジン、冪等キー、秘密情報検出（口座番号の扱い） |
| 退職手続きの拡充 | 返却確認タスクに加え、アカウント停止・資産返却の完了確認・返却されない資産の督促タスク | 退職予定者の自動化、資産の返却処理 |
| 発注点の提案 | 出庫実績（月別）から、最低在庫数・適正在庫数の見直し案を表示（自動変更はしない） | 入出庫履歴、在庫分析の月別集計 |

## 3. 機能（優先度：中）

| 項目 | 内容 |
| --- | --- |
| バーコード・QR | 資産ラベルの印刷と、スマホのカメラでの読み取り（貸出・返却・棚卸を速くする）。実機検証が前提 |
| 保守・保証期限の管理 | 保証期限・リース満了の近い資産を通知し、更新・返却のタスクを提案 |
| 機器ルールの編集画面 | 現在はデフォルトの機器ルール（全社共通＋部署別）を使用。設定画面で追加・編集できるようにする |
| CSV インポート | 品目・資産の一括登録（検証・プレビュー付き） |
| 一括操作 | 資産の複数選択による状態変更・保管場所変更（取り消し可能にする） |
| 分類ルールの改善支援 | 担当者がカテゴリを変更した事例から追加キーワードを提案 |
| 祝日カレンダー | 期限計算・入荷予定日の計算を祝日に対応 |
| PWA 化 | オフライン表示・ホーム画面アイコン |

## 4. 実運用に向けた基盤（デモ環境からの移行）

現在は**デモ環境**であり、以下を備えていない。実運用には必須。

| 項目 | 内容 |
| --- | --- |
| バックエンドと認証 | 複数端末・複数ユーザーでデータを共有するため、サーバーとログインを導入。サービス層を API の背後へ移す（ドメイン層・自動化エンジンは純粋関数なので移植可能） |
| 権限管理 | 管理者・承認者・担当者・一般社員の役割。発注の承認は承認者のみ、品目マスタ・機器ルールの編集は管理者のみ |
| 同時更新の制御 | 複数ユーザーが同じ在庫を同時に操作する場合の排他制御（現在はブラウザ内のトランザクションのみ）。サーバー側でも入出庫履歴と在庫の一致を保証する |
| 監査ログ | 操作者の記録、改ざん防止。承認者の本人確認 |
| 差分更新 | 変更のたびの全データ再読込をやめ、変更分だけ反映 |
| 会計との連携方針 | 資産の取得価額・減価償却・在庫評価は会計方針に依存するため、会計システムへの連携方式（CSV 等）を検討。WorkCore の参考在庫額は会計評価ではない |

## 5. 作業順（案）
1. 実機検証・性能測定と、見つかった不具合の修正
2. 承認フロー（請求書処理と自動化の両方で必要）
3. 請求書・領収書処理（発注書・入荷記録との照合を含む）
4. 退職手続きの拡充・機器ルールの編集画面
5. バックエンド・認証・権限（実運用を始める場合）

外部への発注・メール送信・決済・外部AI・有料サービスは、Phase 4 でも利用しない前提で計画している（利用する場合は事前にオーナーの承認を得る）。
