## 4. 検証中に発見・修正した不具合

| 不具合 | 原因 | 修正 |
| --- | --- | --- |
| 在庫反映のモーダルを閉じた直後に別の画面へ移ると、元の画面に戻されることがある（Phase 4 の E2E で検出） | モーダルを閉じるときの「履歴を1つ戻す」処理は非同期。その完了前に移動すると、Chromium は戻る処理で移動を取り消す | アプリ自身の戻る処理中の移動を記録し、戻り終えてから移動し直す。`navigate()` は戻り終えるまで待つ |
| 連絡先の電話番号を消すと、連絡先欄が閉じて入力できなくなる | 欄の開閉を「値があるか」で決めていた | 開閉は利用者の操作に任せる |
| 電話番号を入力した直後に「登録する」を押すと、整形前の値で保存される | 欄を離れた時の整形が非同期（ライブラリの遅延読み込み）で、保存が先に始まる | 保存処理の中でも同じ整形をかける（社員・仕入先） |
| 該当する住所ファイルが無い郵便番号で「取得できませんでした」と表示される（開発サーバー） | サーバーが 404 の代わりにアプリのページ（HTML）を返す | JSON 以外の応答は「該当なし」として扱う |

## 5. 未検証・制約

- **実機 iPhone Safari**：標準のスワイプ戻りとの共存、ホーム画面に追加した単独起動モードでの独自スワイプ、日本語キーボード（変換中）での電話番号・郵便番号の入力、電話番号キーボードの表示、住所の自動入力（ブラウザの自動入力機能との併用）は未検証
- 独自スワイプは単独起動モードのときだけ有効。Android の戻るジェスチャー・ブラウザの戻るボタンは履歴そのものを使うため、モーダル → 画面の順に戻る
- 郵便番号データは日本郵便の KEN_ALL（npm パッケージ jp-postal 経由）をビルド時に変換したもの。事業所の個別番号は含まない。データ更新はパッケージの更新で行う
- 電話番号の整形は libphonenumber-js（最小メタデータ）の日本の番号規則による。番号が実在するかは確認しない
- AI モデルは接続していない。分類・要約はルールベースで、画面にも「ルールベース（AIではありません）」と表示。外部AIサービスへの送信は行わない（`src/ai/assist.ts` の差し替え口のみ用意）
