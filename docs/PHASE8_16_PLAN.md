# Phase 8〜16 統合開発計画 — 基盤品質・信頼性・セキュリティ・業務UXの全面強化

作成：2026-10-16（Phase 7 完了時点）
目的：WorkCore を「多機能な試作アプリ」から「長期間、安全・安定・効率的に使える業務管理システム」へ発展させる。各 Phase で調査・設計・実装・テスト・検証を完了させてから次へ進む。

## 0. 共通ルール

| 項目 | 内容 |
| --- | --- |
| 品質ゲート（各 Phase の完了条件） | ①実装内容と変更理由の記録 ②型チェック ③単体・結合テスト ④重要業務の E2E ⑤既存機能の回帰テスト ⑥データ互換性・移行の検証 ⑦本番ビルド ⑧未解決事項とリスクの報告。テストが通らない状態で次へ進まない。未確認の項目は「未検証」と明記 |
| 外部サービス | Phase 13 まではローカル構成（GitHub Pages＋ブラウザ内保存）を維持。Phase 14 以降で認証・クラウドDB・ホスティング・有料API を導入する場合は、サービス選定・費用・送信データ・リスクを説明し、**オーナーの承認を得てから**実装する。アカウント登録・課金・外部送信・実在の個人情報の移行は無断で行わない |
| 既存資産 | Phase 1〜7 の機能・既存データ・バックアップ互換性を維持。全面的な書き直しはしない |
| 開発操作 | GitHub への push・GitHub Pages への公開は CLAUDE.md の承認に従って自動で行う |
| 記録 | 各 Phase の `docs/PHASE{n}_RESULTS.md` に、開始時の課題・変更したファイル・設計変更・実装した機能・修正した不具合・実施したテストと結果・残存リスク・次への引き継ぎを記録 |

進捗状態：未着手 / 調査中 / 設計完了 / 実装中 / 検証中 / 完了 / 保留

## 1. 依存関係

```
Phase 8 監査・品質保証基盤 ─┬─▶ Phase 9 データ整合性・保護・復旧 ─┐
                            ├─▶ Phase 10 業務フローUX・アクセシビリティ ├─▶ Phase 13 複数ユーザー・クラウドの設計
                            ├─▶ Phase 11 セキュリティ・監査ログ・個人情報 ┤        │（オーナー承認）
                            └─▶ Phase 12 性能・日付・拡張性 ─────────────┘        ▼
                                                                 Phase 14 認証・権限・企業間分離（外部基盤）
                                                                                  ▼
                                                                 Phase 15 共有DB・同期・安全な移行
                                                                                  ▼
                                                                 Phase 16 本番運用・障害対応・最終検証
```

- Phase 8 のリスク一覧・テストマトリクス・CI が、以降すべての変更の安全網になる
- Phase 9〜12 はローカル構成で完結し、Phase 8 の後は順に進める（9 → 10 → 11 → 12）。P0/P1 の問題は Phase を待たずに対処する
- Phase 13（設計）が完了し、オーナーの承認を得るまで Phase 14 以降は**保留**
