## 3. UX 改善効果の記録

### 3.1 操作回数（**実測値**：E2E で操作を数えた結果）
計測方法：`e2e/helpdesk.spec.ts` でタップ・選択・文字入力をそれぞれ1操作として数えた（画面のスクロールは含まない）。

| 作業 | iPhone | PC | 内訳 |
| --- | --- | --- | --- |
| 問い合わせ登録（ダッシュボードから受付完了まで） | 6操作 | 6操作 | タップ4（ナビ・登録・申請者選択・受け付ける）＋入力2（件名・詳細） |
| 対応タスクの登録（詳細画面から） | 3操作 | 3操作 | 作成ボタン・1件の選択解除・承認 |
| 問い合わせの完了 | 3操作 | 3操作 | 完了にする・申請者確認・確定 |
| FAQ検索（手順を表示するまで） | 4操作 | 3操作 | スマホはメニュー経由のため1タップ多い |

### 3.2 同じ情報の再入力回数（**実測値**：画面仕様と E2E で確認）
| 情報 | WorkCore での入力 |
| --- | --- |
| 申請者の氏名・所属部署 | 社員マスタから選択するだけ（部署の入力0回、E2E で自動表示を確認） |
| カテゴリ・優先度 | 自動提案（入力0回、変更時のみ1回） |
| 担当者・対応期限 | カテゴリの既定値から自動入力（E2E で担当者の自動入力を確認） |
| 問い合わせ番号・受付日時 | 自動採番・自動記録 |
| タスク名・担当部署・期限・紐付け | 提案から生成（入力0回、調整時のみ） |

### 3.3 手作業との比較（**仮定値**を含む）
手作業の値は、メール・チャットで受けた問い合わせを Excel の管理表とタスク表に転記する運用を**仮定**して見積もったもので、実測ではない。

| 作業 | 手作業（仮定値） | WorkCore（実測値） |
| --- | --- | --- |
| 問い合わせの記録 | 管理表に番号・日時・氏名・部署・件名・内容・カテゴリ・優先度・担当・期限の約10項目を入力（仮定） | 6操作（文字入力は件名・詳細の2回） |
| 対応タスクの登録 | タスク表に作業ごとに作業名・担当・期限・問い合わせ番号を入力（2件で約8項目、仮定） | 3操作 |
| 分類・振り分けの判断 | 担当者が内容を読んで判断（1件あたり1〜2分と仮定） | 自動分類 0.08ms/件（実測、下表）＋担当者の確認 |
| FAQ・過去対応の検索 | 共有フォルダやメールを検索（数分と仮定） | 入力中に候補を自動表示（0操作）、FAQ画面からは3〜4操作 |

### 3.4 自動処理の所要時間（**実測値**）
Node.js 22 上でデモデータ（問い合わせ15件・FAQ9件）を使い、各処理を2,000回（集計は200回）実行した平均。

| 処理 | 1回あたり |
| --- | --- |
| 自動分類（カテゴリ＋優先度） | 0.078 ms |
| FAQ候補の検索 | 0.049 ms |
| 過去事例の検索 | 0.051 ms |
| 対応タスクの提案 | 0.012 ms |
| ヘルプデスク分析の全指標集計 | 0.129 ms |

ブラウザ（特に iPhone 実機）での所要時間は計測していない。
