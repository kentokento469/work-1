# Phase 6 開発計画（案）— Phase 5 からの引き継ぎ

Phase 5 で、部門をまたぐ自動化を1つのルール一覧（自動化センター）にまとめ、入力補助（電話番号・郵便番号・金額・候補）と戻る操作（履歴・モーダル・スワイプ）を共通部品にした。
Phase 6 では、実機での検証を最優先にし、承認フローと書類の照合で「確認 → 確定」の流れを完成させる。

## 1. 最初に行うこと（実機検証）

| 項目 | 内容 |
| --- | --- |
| iPhone Safari（タブ） | 標準のスワイプ戻りで一覧の条件・スクロール位置が残るか、モーダルが先に閉じるか、二重に戻らないか |
| ホーム画面に追加（単独起動） | 左端スワイプで戻る・アプリ外へ出ない・入力欄・横スクロールの表やグラフと競合しない。しきい値（画面幅の30%・速度）の調整 |
| 日本語キーボード | 電話番号・郵便番号・金額を変換中に入力したときの挙動、電話番号キーボード、自動入力（連絡先・住所）との併用 |
| Phase 1〜4 の持ち越し | カメラ撮影・HEIC・共有シート・OCR の速度とメモリ・保存容量の上限 |

## 2. 自動化ルールの追加（Phase 5 の拡張点を使う）

ルールは `src/automation/registry.ts` の `ALL_AUTOMATIONS` に追加するだけで、自動化センターの一覧・有効/無効・実行方法の設定・処理履歴・二重実行防止がそのまま使える。

| 自動化 | 実行条件 | 実行内容 | 実行方法 |
| --- | --- | --- | --- |
| 請求書 → 支払確認タスク | 確認済みの請求書に支払期限 | 期限の数日前のタスク | 自動可（タスクのみ） |
| 請求書・納品書・発注書の照合 | 同じ取引先・番号の書類がそろう | 数量・単価・金額の差異を表示 | 要承認 |
| 確認待ちの滞留 | 書類・問い合わせが一定日数未処理 | 担当者への確認タスク | 自動可 |
| 退職 → 貸与機器・書類の一括確認 | 退職日の確定 | Phase 5 の退職手続きと機器返却の提案をまとめて表示 | 要承認 |
| 入社日の変更 | 入社準備タスクの期限とずれる | 期限の変更を提案（Phase 3 の機器予約の変更と同じ方式） | 要承認 |

## 3. 機能（優先度：中）

| 項目 | 内容 |
| --- | --- |
| 承認フロー | 発注書・書類・自動化提案の「申請 → 承認 → 確定」を共通化（承認者・差し戻し理由・期限） |
| ルールの編集画面 | 機器ルール・退職手続きのタスクを画面から編集（現在は初期設定） |
| 入力補助の拡大 | 日付の自然な入力（「来週月曜」など）、取引先・品目の候補を書類・発注書の全入力欄へ |
| AI 連携（任意） | `src/ai/assist.ts` の `AssistProvider` に実モデルを実装。**外部送信は利用者の許可・設定・送信内容の表示が前提**。費用が発生するサービスはオーナーの承認後に導入 |
| PWA 化 | Service Worker でアプリ本体もオフライン化（現在は OCR・郵便番号データのみ） |

## 4. 実運用に向けた基盤（変わらず必要）

認証・権限管理・複数ユーザーの同時利用・サーバー側のデータ保護・監査ログは未実装（デモ環境）。個人の連絡先（電話番号・住所）を扱うため、実運用では閲覧権限と保存場所の方針を先に決める必要がある。外部への送信・有料サービスの利用は、オーナーの承認を得てから行う。
