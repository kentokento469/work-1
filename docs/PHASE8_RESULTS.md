## 1. 開始時の課題

- 機能は Phase 1〜7 で拡大したが、削除・復元・障害時の動作を横断的に検証していなかった

### 5.2 品質基準（以降の Phase で守る基準）

1. main に入る変更は、型チェック・単体テスト・E2E（iPhone 相当・デスクトップ）・ビルド・`npm audit`（high 以上なし）がすべて成功していること（CI で強制）
2. データ形式を変える変更は、①旧版の DB を開く単体テスト ②旧版のバックアップの復元テスト ③実ブラウザでの移行 E2E を追加する
3. 削除・置き換えの処理を追加・変更したら、`backupIntegrity.test.ts` に「その操作の後のバックアップが修復なしで復元できる」テストを追加する
4. 通知を追加したら、`NOTICE_SPECS` と「通知の約束」E2E に操作手順を追加する（Phase 6.1）
5. E2E は固定日時（`e2e/fixtures.ts`）で実行し、テスト側の日付計算も `testNow()` を使う
6. 既存テストの期待を変える場合は、意図した仕様変更であることを結果の文書に記録する
7. 実機・WebKit で確認していない項目は「未検証」と明記する
