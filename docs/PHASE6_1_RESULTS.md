# Phase 6.1 — 通知・警告から対象業務へ遷移できない問題の修正と再発防止

実施日：2026-10-16
環境：Node.js 22 / Chromium（Playwright 1.56）。「iPhone」は Chromium の iPhone 13 エミュレーション（実機では未検証）。

## 1. 不具合の原因

| 項目 | 内容 |
| --- | --- |
| 現象 | 入社準備の通知・警告（例：森 結衣さん、入社日 10/19 まであと3日、未完了の準備タスク5件）を押しても、未完了の5件を確認・完了できない |
| 直接の原因 | `src/domain/notifications.ts` の入社準備通知の遷移先が `#/onboarding?employee=社員ID`。`OnboardingPage` は「タスクの自動生成（プレビュー → 登録）」の画面で、作成済みの未完了タスクを完了・編集する操作がない |
| 根本の原因 | 通知の「必要な操作」の文言と遷移先を、通知ごとに個別に書いていた。**通知が求める操作が、遷移先で実行できるか**を定義・検証する仕組みがなく、E2E も「移動できること」までしか確認していなかった |

## 2. 修正した箇所

| ファイル | 修正 |
| --- | --- |
| `src/domain/notifications.ts` | 通知の種類ごとの定義 `NOTICE_SPECS`（対象の種類・移動先の種類〔詳細／一覧で強調／絞り込んだ一覧〕・移動先で行う操作・解消条件・ボタン文言）を追加し、通知の生成はこの定義を通す。入社準備の通知は `hireTasksHref()`＝`#/tasks?employee=ID&source=onboarding&status=open` へ。各通知に `actionLabel`（移動ボタンの文言）を追加 |
| `src/pages/TasksPage.tsx` | 社員で絞り込んだ時に「○○さんの入社準備タスク」と、その社員の通知（理由・残り件数）を表示。他の社員の「要対応」は混ぜない。全件完了時は「すべて完了しました」。存在しない社員 ID は案内を表示 |
| `src/ui/notices.tsx` | 詳細画面などの警告バナー（`TargetNotices`）に、操作する画面が別の場合だけ移動ボタン（例：「未完了の準備タスクを開く」）を表示。同じ画面で操作できる場合はボタンを出さない（説明だけの表示を押せそうに見せない） |
| `src/pages/inventory/InventoryPage.tsx`・`DetailPages.tsx` | 在庫不足の通知・品目詳細の「発注候補があります」から、対象の発注候補を強調し、その候補だけを選んだ状態で表示（`focus=sug:ID`）。候補が無ければ案内 |
| `src/pages/DashboardPage.tsx` | 「優先対応が必要な業務」は通知（「対応が必要なこと」）と重複していたため、通知に含まれない「3日以内に期限のタスク」「入社準備タスクが未生成の社員」だけに整理 |
| `src/features/TaskItem.tsx` | テスト・強調表示用の属性（対象社員・状態） |

## 4. 再発防止策

1. **通知の定義を1か所に**：`NOTICE_SPECS` に、種類ごとの対象・移動先の種類・移動先で行う操作・解消条件・ボタン文言を定義。型（`Record<NoticeType, NoticeSpec>`）により、通知の種類を追加すると定義の追加が必須になる
2. **単体テスト（約束の検査）**：全通知について、移動先が実在する画面の形であること、移動先の種類（詳細なら対象 ID、一覧なら focus）と定義が一致すること、操作・ボタン文言があることを検査。入社準備・在庫不足は段階ごとの移動先と解消までを検査
3. **E2E（操作の完了まで）**：通知から移動し、**移動先で操作を実行して通知が更新・解消されること**までを確認（`e2e/phase6-1.spec.ts`）。新しい通知を追加したら、ここに操作手順を追加する（定義ファイルのコメントに明記）
4. **警告バナーの共通化**：操作する画面が別なら必ず移動ボタンを出す仕組みを `TargetNotices` に持たせ、画面ごとに個別実装しない

## 6. 未解決の問題・制約

- 実機 iPhone Safari では未検証（Phase 5・6 から継続）
- 在庫不足は「発注書の承認」で見込み在庫に入るまで通知が残る（下書きの段階では次の操作として承認申請を案内）。在庫の実数は入荷登録で増える
- 入社準備の通知は「入社まで7日以内」の社員が対象。それより先の社員は、ダッシュボード「入社予定者の準備状況」と入社準備画面で確認する
